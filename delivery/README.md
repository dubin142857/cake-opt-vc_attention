# 交付说明 — Ascend 910B2 数据流优化

> **本目录是唯一入口。** 仓库顶层有甲方自己的 40 多个文档，本次交付的全部内容都在这里。

| 文件 | 内容 |
| --- | --- |
| **`README.md`**（本文） | 做了什么、收益多少、口径边界 |
| **`TECHNICAL_REPORT.md`** | 五处改动的机理、证据、正确性 |
| **`REPRODUCE.md`** | 从基线复现的完整步骤 |
| `OPTIONAL_FP16_S.md` | **可选级存档**：QK 直出 fp16。它在本验收判据下不通过，不在交付内，收益与代价见该文 |

## 一句话

在甲方基线 `9e3a550d399c560cc7c7d9e25cbbc4157e82c0d5` 上叠加五处数据流与同步时序的改动，
长形状固定核心用时下降 **70.0%**。不改算子的对外契约，不改数值路径（或只改表示粒度）。

## 收益

单一形状 `[B=1, N=37741, H=28, D=128]` BF16，自注意力，`tile_m=64`，
只计 `run_prepared()` 的原生核心调用（`prepare()` 在计时之外）：

| | `control_m64` | `expcast_m64` |
| --- | ---: | ---: |
| 基线 `9e3a550` | 1103.51 ms | 1230.62 ms |
| 本交付 | **331.37 ms（−70.0%）** | **354.45 ms（−71.2%）** |

同机 CANN `npu_fusion_attention` 为 144.7 ms；差距由基线的 7.6 倍收窄到 **2.3 倍**。
★这是两个不同数值契约的算子，该比值只作背景参照，**不是加速比**。

## 五处改动

| # | 改动 | 对前一级 |
| --- | --- | ---: |
| 1 | 推迟 `O_USED` 等待，让下一 tile 的 QK 与 AIV 尾段重叠 | −26.48% |
| 2 | `Brcb` 广播替代「标量回读 + ROWS 次短向量调用」 | −16.28% |
| 3 | matmul tile 128→256，并把 K 的量化块与 tile 宽度解耦 | −23.68% |
| 4 | S 双缓冲，AIC 在等 `P_READY` 之前预发下一块 QK | −12.49% |
| 5 | AIV 推迟累加，等 PV 的时间用来算下一块的概率 | **−28.98%** |

机理与证据见 `TECHNICAL_REPORT.md`。

## 三条口径边界（请勿略过）

1. **这是一个形状的结果，不是形状扫描。** 我们没有做过性能的形状扫描。
   仓库里那 141 个用例是**正确性**套件，不测时间。
2. **是核心调用时间，不是端到端。** `prepare()` 的预处理被排除在外，
   完整 API 的收益会被预处理摊薄。
3. **语义层级是现有端口的 v1 子集。** `ascend/vc_attention_ascend/api.py` 自己声明
   `causal` 与 `v_smooth` 未实现；对照仓库自身的 `PAPER_ALIGNMENT.md`，论文中负责精度的
   两大机制（Q/K 共同归一化 Hadamard 旋转、V-Smooth 全套）不在该端口内。
   **因此 70% 是「该子集算子」的数据流收益，不等于「VC-Attention 快了 70%」。**
   这五处改动都不碰数值路径或只改表示粒度，预期可平移到含 V-Smooth 的版本，但需重新实测。

## 正确性

| 闸门 | 结果 |
| --- | --- |
| `scripts/validate_ascend910b.py` | `status=passed`，141 个用例，0 个超 1% |
| `scripts/profile_ascend910b.py` 长形状 | `accuracy_status=passed` |
| `decoded_reference` 相对 RMSE | control 0.000068 / expcast 0.000043 |
| `dense_fp32` 相对 RMSE | control 0.029799 / expcast 0.043645 |
| 逐位重复性 | 6 组形状各连发 8 次，全部 8/8 相同 |

改动 1、2、4、5 对各自前一级**逐位一致**；改动 3 改变了 ExpCast 的 tile 宽度契约，
实测为质量中性（12 个可判别用例，相对 dense 的误差变化 −1.29% 至 +1.44%，8/12 改善）。

## 环境

CANN 9.0.0，`Ascend910B2`（`npu-smi` 25.5.1），torch 2.9.0 + torch_npu 2.9.0，
Python 3.10，aarch64。在 910C / A3 上跨核标志的实现与调度不保证一致，请独立实测，
不要据本侧数字推断加速比。
