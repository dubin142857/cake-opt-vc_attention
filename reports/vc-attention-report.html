03 / MEASURED, NOT ASSUMED

把收益放回正确的测量范围。

同轮、同输入、同 API 的对照，才能判断改动是否有价值。局部微基准、整核计时和完整算子耗时分别回答不同问题。

FULL API

从原始 Q / K / V 开始

包含本次调用的聚类、重排、量化、分配、调度和 attention。回答“应用替换这个算子，调用快了多少”。仍不包含模型其他层。

FIXED CORE API

固定量化后的输入

提前准备量化张量，只测 native attention API，仍包含其输出分配与调度。适合排除预处理后定位内核改动。

CUPTI / CUDA EVENTS

观察 GPU 执行区间

CUPTI 给出 kernel 活动时长；CUDA event 分阶段区间可能含流空隙。它们与同步 API 墙钟时间口径不同，不能混加或互相替代。

Flash 的核心：不把大矩阵写回显存

按块读取 Q / K / V，只保存每行的最大值、归一化和及输出累加器，最后完成归一化。避免显式保存 N × N 中间矩阵，但仍覆盖全部 token 对，仍是 dense attention。

m′ = max(m, rowmax(S))
α = exp(m − m′)
l′ = αl + sum(exp(S − m′))
U′ = αU + exp(S − m′)V
O = U / l

在线 softmax 的通用递推；具体实现会重排运算和精度。FlashAttention 原始论文。

低比特的核心：让矩阵乘更便宜

这条 Sage H200 路径已经量化 V。VC 的新增点是改善 V 量化方式，以及更省地得到 FP8 概率。

INT8：整数 + scale

同一缩放范围内间距固定，适合中心化后细粒度量化的 Q / K；大异常值可能挤占量化区间。

FP8：指数 + 尾数 + scale

动态范围更灵活，E4M3 只有 3 位显式尾数；适合低比特 PV，但不等同于 BF16 精度。

是否更快取决于整条流水线

矩阵乘变快后，布局、量化、概率编码和同步可能变成新的等待点，不能仅按 bit 数预测速度。

Python import 是入口。Sage 与我们当前的主 attention 运算由原生 CUDA 内核执行；FA4 的 Python DSL 也编译成 GPU 代码。“Python 写接口”与“CPU 算 attention”是两回事。
05 / WHAT WE ADDED

V-Smooth 处理误差，ExpCast 争取速度。

两个开关独立验证。它们改变低精度计算的行为，也带来工程成本，需要分别看精度和性能。

V-SMOOTH

先聚类，再减均值，最后补回来。

按 V 的相似度做在线 k-means

每个 batch / head 内将 token 分配给中心，迭代更新中心；按标签稳定排序，K 和 V 使用同一个排列。

在硬件块内减掉共有分量

对重排后的 V 块求均值 μ，只量化残差 R = V − μ。聚类让相似的大值更可能进入同一块。

用该块概率行和恢复均值

每块均值不同，须按该块注意力权重补偿，不能在输出上随便加一次全局均值。

Vb = Rb + 1μbᵀ
PbVb = PbRb + (Pb1)μbᵀ

示意：原顺序，每两个元素为一个块

10−1010.5−9.5

按相似性重排后，块内残差变小

1010.5−10−9.5

两个块均值为 10.25 和 −9.75，残差都只有 ±0.25。这是示意，随机张量和实际模型不保证获得同样收益。

忽略量化时，同时置换 K / V 不改变无掩码 attention 的输出；causal mask 下不能直接任意重排。此处没有跳过 QK 计算，因此不是稀疏 attention。本地实现与约束。

EXPCAST-FP8

直接构造浮点编码，近似指数。

正 E4M3 编码随数值近似按对数增长。用线性映射把减最大值后的分数 x 直接映射到 FP8 字节，省去常规“FP32 exp → 数值转换 FP8”路径。

x = S − m ≤ 0
a = 8 · log₂(e) ≈ 11.54156
b = 120 − 0.35 = 119.65
c = clamp(RNE(a·x + b), 0, 120)
P̃ = decode_E4M3(c)

RNE 是最近偶数舍入；decode 按 E4M3 位模式解释字节。这里近似缩放权重 256·exp(x)，共同缩放因子在归一化时消除。

256 · exp(x)34.6458
ExpCast 权重32.0000
FP8 字节编码96

数学公式示意，使用浏览器数值运算；不是 CUDA FMA 逐位模拟，也不是输出误差上界。

主内核仍需行最大值、舍入打包、量化 P 解码求和及历史重缩放。它没有消除整个 softmax；新增指令和依赖处理不好，仍可能更慢。

数值约定：本地实现；方法出处：VC-Attention §3.3。

06 / WHAT THE EXPERIMENTS TAUGHT US

瓶颈在整条依赖链，不只在 exp。

省掉一类指令后，新增搬运、寄存器占用和等待可能抵消收益。实验已排除了一批“理论更并行、实际更慢”的方案。

为什么“优化”会变慢？

  • 副本有成本，重叠不一定赚回来。

    vc13 为 PV 期间求和新增共享内存副本，core 从 27.43 升到 30.71 ms；这个实现的净收益为负，“能重叠”不等于“能提速”。

  • 多并行一块，也可能放不下寄存器。

    vc20 同时保留 QK / PV 累加器，寄存器增至 206–224，预测驻留 block 从 3 降到 2，候选全部变慢。vc18 强限寄存器又出现 local spill。

  • occupancy 更高不自动等于更快。

    vc21 用共享内存换来 128 寄存器、预测 4 blocks / SM，完整 API 仍变慢。资源驻留指标不是 GPU 利用率或性能保证。

  • 少做热循环工作更有效。

    vc22 组合 INT32 / DPX 最大值归约与跳过无效历史缩放，在资源占用不变时获得收益。具体 stall 占比仍需硬件计数器确认。

与论文完整实现还有哪些差距？

  • 量化格式已对齐，完整融合仍有差距

    2026-10-08 勘误：作者主流程为 INT8 QK、FP8 PV；FP8 QK 是 B300 等场景的另一变体，不能作为 H200 的必选条件。我们继续沿 INT8 路线推进，仍缺少 Hadamard 及相关预处理融合。

  • V 平滑预处理尚有成本

    融合聚类后，每次开启仍做 fresh grouping、重排及残差量化。论文按去噪步数启用 grouping 的策略尚未接入模型流程。

  • 与模型前后操作未完全融合

    当前是独立算子实验。RoPE、相关变换、重排与量化能否继续合并，要结合模型调用边界设计。

  • 固定 shape 的成功还需泛化

    目前重点是 H200、BF16、D128、约 3.8 万 token。长度、head 数、输入分布及极端值可能改变性能排序和误差。

工程范围：本地实现；论文设计：VC-Attention。

01 / IMPLEMENTATION

有没有把原算法改坏？

固定量化输入，检查全部输出行，优化版与同算法基线相对 RMSE ≤ 0.1%。这是实现回归门槛。打印为 0.000000% 不自动意味着逐位相同。

02 / OPERATOR ERROR

离 dense FP32 有多远？

早期随机输入，Sage 约 3.87%、混合全开约 4.17%；vc6 改用 channel V scale 后全开约 4.21%。这是当时抽样 query 的结果，不代表当前所有输入的质量。

03 / MODEL QUALITY

业务输出是否能接受？

需要真实 QKV 回放，以及生成质量、稳定性和模型完整推理计时。当前未完成模型级验收，不能只凭算子 RMSE 宣布“精度够用”。

历史精度及取样范围见 阶段记录、vc6 / vc9 实测。论文模型指标与随机张量 RMSE 不同。

07 / NEXT MILESTONE

守住已有收益，向 22 ms 推进。

以 vc22 为实验比较基线。先判断关键路径能否缩短，再评估 V 平滑和真实模型效果。

01

减少概率与归一化的串行等待

围绕编码 → 解码行和 → 历史更新 → 下一块 QK 的依赖安排实验。vc25 延迟行和调度已在本报告范围之后提交，H200 性能待回传，本页没有将它计入成果。

02

以完整 API 接受或否决候选

同轮交错测 Sage / vc22 / 新候选；先检查所有输出，再看多轮完整 API 中位数与重复 CUPTI 方向。22 ms 目标要求在当前基础上再降低约 14.3% 耗时。

03

让 V-Smooth 接受真实模型验证

回放真实 QKV，检查各层、head、去噪步误差；评估聚类价值、接入分步调度，验证预处理融合收益。

04

完成模型验收，再推广默认路径

质量与端到端耗时通过后扩大 shape 覆盖并调整公共默认模式。保留显式实验入口，方便复现、回退和核查。
